# Newsletter buttons — design spec

Дата: 2026-06-23
Модуль: `apps/admin_miniapp` (Vue 3 SPA, frontend-only — бэкенд рассылки пока заглушка)

## Цель

На вкладке Newsletter дать возможность настроить кнопки сообщения: переключатель
типа клавиатуры **Inline / Reply** и редактируемый список кнопок. Это новые поля
payload для будущего бэкенда `POST /telegram/newsletter`.

Семантика повторяет Telegram:
- **Reply** (`KeyboardButton`) — только текст.
- **Inline** (`InlineKeyboardButton`) — текст + ровно одно из `url` / `callback_data`
  (взаимоисключающие).

Раскладка: **вертикальный список** — одна кнопка в ряд.

## Компоненты

### `components/newsletter/KeyboardEditor.vue` (новый)

Рендерится внутри `MessageComposer.vue` под полем вложения. Вынесен отдельно, чтобы
не раздувать `MessageComposer`. Привязан к стору через геттеры/экшены.

UI-структура:

```
Кнопки
[ Inline | Reply ]   ← сегментед-тоггл типа клавиатуры

— список кнопок (каждая = строка) —
  Inline-строка:  [ текст ] [ url ] [ callback_data ] [✕]
  Reply-строка:   [ текст ] [✕]

        [ + Добавить кнопку ]
```

Поведение:
- **Исчезающие поля (inline):** `url` и `callback_data` показываются, пока оба пусты.
  Как только в одном появился непустой текст — второе поле скрывается. Когда активное
  поле снова очищено до пустого — второе снова появляется.
- **Переключение Inline↔Reply** не теряет введённый `text` (список кнопок общий),
  просто скрывает/показывает `url` / `callback_data`.
- **`✕`** удаляет строку.
- **`+ Добавить кнопку`** заблокирована, если последняя кнопка в списке невалидна
  (для текущего типа). Пустой список → добавлять можно. Это не даёт накопить хвост
  из пустых кнопок.

### `MessageComposer.vue` (изменение)

Добавить `<KeyboardEditor />` под `BaseFileInput`. Кнопка «Разослать» дополнительно
блокируется при `!store.keyboardValid`; рядом со списком показывается `store.keyboardError`.

### `NewsletterConfirmDialog.vue` (изменение)

Добавить строку-сводку: `Кнопки: 3 (inline)` либо `— нет —`.

## Стор (`stores/newsletter.js`)

State:

```js
keyboard: { type: 'inline', buttons: [] }  // type: 'inline' | 'reply'
// кнопка: { text: '', url: '', callback_data: '' }
```

Экшены: `setKeyboardType(type)`, `addButton()`, `updateButton(index, patch)`,
`removeButton(index)`.

Геттеры:
- `keyboardValid: boolean` — все кнопки валидны (или список пуст).
- `keyboardError: string | null` — текст первой ошибки, напр.
  «Кнопка 2: укажите ссылку или callback_data».
- `canAddButton: boolean` — список пуст ИЛИ последняя кнопка валидна.

`reset()` и успешная отправка чистят `keyboard` (вместе с `text` / `file`); аудиторию
оставляем как есть.

## Валидация

Кнопка валидна, если:
- `text` непустой (после `trim`), **и**
- для `inline` — ровно одно из `url` / `callback_data` непусто;
- для `reply` — достаточно `text`.

Пустой список = валиден (клавиатуры нет). Отправка блокируется при `!keyboardValid`.

## Контракт с бэкендом

В `FormData` (метод `send()` стора) добавляется **одно** поле `keyboard` — JSON-строка,
и только если есть валидные кнопки:

```json
{
  "type": "inline",
  "buttons": [
    { "text": "Открыть сайт", "url": "https://..." },
    { "text": "Подробнее", "callback_data": "more" }
  ]
}
```

Для reply: `{ "type": "reply", "buttons": [ { "text": "Да" }, { "text": "Нет" } ] }`.

Правила сериализации:
- у inline-кнопки кладётся только заполненный ключ (`url` **или** `callback_data`),
  пустые ключи не отправляются;
- вертикальный список → каждая кнопка = отдельный ряд на стороне бэкенда;
- поле `keyboard` отсутствует в payload, если кнопок нет.

Бэкенд (`POST /telegram/newsletter`) пока заглушка (`mockSend`), как и весь модуль
рассылки. Контракт фиксируется для того, кто будет писать бэкенд.
