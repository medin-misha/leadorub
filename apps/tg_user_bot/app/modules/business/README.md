# Модуль business

Продуктовая воронка DMCAGuardian для агентств — презентационный слой
команды `/start business` (deep link `t.me/<bot>?start=business`).

## Что делает

Системный хендлер `/start` после провижининга пользователя проверяет
deep-link payload: если это `business`, вызывается `run_start_funnel`
этого модуля, и он отправляет цепочку:

1. приветственный текст — питч гайда для агентств;
2. PDF-гайд из `BUSINESS_GUIDE_PATH` с подписью «📎 Ваш гайд…»
   (с паузой ~2 секунды, как и обещает текст);
3. видео из `BUSINESS_VIDEO_PATH` с подписью и двумя inline-кнопками:
   - «✍️ Написать» — ссылка на аккаунт админа (`ADMIN_CONTACT_URL`);
   - «📩 Оставить заявку» — WebApp-кнопка Client MiniApp (`CLIENT_MINIAPP_URL`);
4. выставляет пользователю состояние `business_start` в backend
   (`PUT /api/telegram/state`, сервисный токен).

`/start` без payload и с любым другим payload (включая `source_*`)
обрабатывает модуль `persona`.

## Устойчивость

- Отсутствующий файл гайда или видео логируется и пропускается — цепочка
  не падает. Если нет видео, подпись с кнопками уходит обычным сообщением,
  чтобы кнопки связи всё равно дошли до пользователя.
- Ошибка backend при выставлении state только логируется: UX `/start`
  важнее фиксации состояния.
- Кнопка «Написать» не показывается, если `ADMIN_CONTACT_URL` не настроен.

## Почему нет router

Обе кнопки — URL и WebApp, их обрабатывает клиент Telegram, callback'ов нет.
Поэтому модуль ничего не регистрирует в `app/bot/registry.py`, а состоит из
сервиса, клавиатур и текстов.

## Ограничения

- Подписи к PDF и видео должны укладываться в лимит Telegram 1024 символа —
  это проверяет `tests/test_business_funnel.py`.
- Состояние пользователя живёт в backend (`user_stats.state`), бот ничего
  не хранит локально.
- Пути к ассетам по умолчанию указывают на те же файлы, что и у persona
  (`sila_tvorozhka.pdf`, `coala.mp4`) — когда появятся отдельные материалы
  для агентств, задайте `BUSINESS_GUIDE_PATH`/`BUSINESS_VIDEO_PATH`.
